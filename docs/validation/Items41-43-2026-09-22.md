## What was not validated

- **No GPU execution.** The container has no video device or Vulkan ICD, and the package mirrors needed to install Mesa llvmpipe/Xvfb were unavailable. Both new native smokes compile and are registered under `SWIM_RUN_RHI_SMOKE=1`; run as-is they stop at `platform.Initialize()`. That failure is expected here and is not GPU evidence. Run them on Windows hardware and Linux llvmpipe under `core`, `sync`, `gpu` and `all`, like item 40:

  ```powershell
  scripts/run-debug-tests.ps1 -SkipBuild -Validation core -Filter 'RHI.Vulkan.Smoke.RenderGraphStaged*'
  scripts/run-debug-tests.ps1 -SkipBuild -Validation core -Filter 'RHI.Vulkan.Smoke.GeometryHeap*'
  ```

  Repeat with `sync`, `gpu`, then `all`, core first. The accepted GPU-AV advisory policy is unchanged.
- **No Windows/MSVC build** in this checkpoint. The new code uses only standard C++20 (`<bit>`, `std::erase_if`, `std::lcm`) plus existing project patterns, but the Windows clean/soft build and its default suite remain the authoritative gate.
- **Formatting:** the repository requires clang-format 22+, which was unavailable. New files and the RenderGraph files touched here were formatted with clang-format 18 using the repository `.clang-format`; version 18 reproduces the existing RenderGraph files byte-for-byte, but `SwimFormatCheck` with version 22 should still be run.

## What the CPU cases prove

The mock device now captures the shared command stream and executes buffer/texture copies against host-backed buffers and textures, so graph transfers are checked end to end without a GPU:

- Upload → device buffer → readback returns the exact payload; readbacks report `NotReady` until the executor's completion value; the upload arena buffer receives a generated `HostWrite → CopySource` barrier and the readback a final `HostRead` transition.
- Partial uploads preserve surrounding bytes of an initialized import and are rejected on uninitialized transients. Texture uploads with a partial patch read back pixel-exact.
- Staging grows only after the predecessor wait (64 KiB → 128 KiB for a 100 KiB payload), is reused afterwards without new buffer creation, honours uniform-offset limits and requested alignments, and is released by `Trim`.
- Throwing writers and failed submissions publish no result; the next execution succeeds and writers run once per execution.
- Registry handles are invalid immediately after release, records die only after their timeline point, slots recycle oldest-first, retiring slots count against capacity, and failed drains keep entries pending.
- GeometryHeap uploads batch one pass per touched page plus one metadata pass; page bytes and uploaded metadata rows match the CPU rows; residency advances only after completion; destroyed ranges and rows are not reused until the (upload-raised) retirement point completes; dedicated pages are released and their slots reused; creation failures roll back every range.

A fixture fix accompanies this: `MockMappedBuffer` now owns its debug name like the Vulkan backend, instead of retaining a caller's temporary `string_view`.
