## What the native cases prove

`RenderGraphOffscreenPostPresentAndReuse` executes four frames of offscreen clear → sampled post → sampled present, then reads the post result back and checks every color byte. It rebuilds the swapchain halfway through, retires graph-owned views before replacement, recreates per-image presentation semaphores, and rebuilds imports. It checks transient reuse and named per-pass GPU timings. Every barrier comes from the graph.

`RenderGraphComputeStorageAndReadback` schedules buffer initialization, two dependent Slang compute passes, and readback across four executions. It checks the generated same-state storage dependency and all 256 output values, including three preserved elements, on every execution. Upload input returns to host-write state; readback exports to host-read state; transient working storage is reused only after completion.

The first rendering run caught a real test-teardown bug: the render timeline had completed while a presentation semaphore was still in use. The test now drains presentation waits before destroying semaphores, including its failure path. Subsequent acceptance runs passed teardown diagnostics on both platforms.
