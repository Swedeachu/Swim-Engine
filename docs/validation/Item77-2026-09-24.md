**Findings of validation layer 1.4.350 in earlier items' code (not changed here):**

1. `SharedMemoryDataRace-RaceOnStore` in item 61's `EnvironmentIrradiance.slang` and item 65's `ClusterScan.slang` reductions (environment, PBR gallery, clustered lighting, Forward+ and shadowed Forward+ smokes). Every flagged site is a `shared[t] op= shared[t + half]` tree reduction whose rounds are separated by `GroupMemoryBarrierWithGroupSync` in uniform control flow; the SPIR-V barriers are workgroup-scope with acquire-release + workgroup-memory semantics, and each report pairs an invocation with itself. A 16-byte element stride did not change the report, and the shared-memory bitonic sorts (this item's finalize pass, Forward+'s transparent sort) pass the same detector. This looks like a false positive of the new detector, but it should be rechecked with the desktop SDK before those smokes are run with a 1.4.34x+ layer.
2. `WARNING-GPU-AV-drawCount` in item 49's `GpuVisibilityCullsBinsAndDrawsIndirect`: `GpuVisibility.slang` counts every draw of a bin (dropped ones included, for the statistics) and relies on `maxDrawCount` = the bin capacity to clamp `DrawIndexedIndirectCount`, which the Vulkan specification allows. The newest GPU-AV checks the raw count against the buffer end and warns. Clamping the count written to the count buffer (keeping the raw one in the statistics) would satisfy both; it was left for item 49's owner.

## Defects found

- **Test-only:**
  - `SWIM_CHECK_EQUAL(system.Simulate(...).Emitters[0]..., ...)` bound a reference to an element of a destroyed temporary (the macro takes `const auto&`), which read garbage; results are now stored first.
  - A double import of one texture into a graph in the first draw test.
  - A bounce test counted resting contact as bounces; it now checks the first three rebounds exactly.
  - A burst expectation ignored the half-open emission interval.
- **Code:**
  - Read-write storage buffers must be declared `ShaderRead | ShaderWrite` in the graph (caught by the graph's validation on the first mock run).
  - `Simulate` now rolls emission clocks and range resets back when recording throws, and `CommitFrame` refreshes the rollback point, so a rejected frame never rewinds a committed one (a new test covers it).
