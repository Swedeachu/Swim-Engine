# Item 78 validation — September 24, 2026

This record covers critical-path item **78**: animation, skinning and morph targets. The contract is in [Animation and skinning](../Animation.md). It adds:

- **Assets:** `SkeletonAsset`, `AnimationClipAsset`, and mesh skin streams and morph targets. Model skins, morph weights, skeletons and animations. `.sasset` asset types 7 and 8, and payload version 2 for meshes and models.
- **Asset compiler:** glTF skins, influences, morph targets and animation channels. The static model compiler emits skeletons (parents first, remapped joints), normalized influences, morphs and clips.
- **`Systems/Animation`:** math, `Skeleton`, `AnimationClip`, blending and masks, `Animator`, `SkeletonInstance`, sockets and the jobified `UpdateAnimations`.
- **`Renderer/Skinning`:** records, bindings, the CPU reference and `SkinningSystem`. The shader is `Shaders/Slang/Skinning` (`SwimSkinning`).
- **GPU Scene and Forward+:** `GpuInstanceRecord::PreviousVertexOffset` (was `Reserved`) and `GpuScene::SetPreviousVertexOffset`. The opaque Forward+ program reads previous positions through it, and `ForwardPlus::MotionVector` gains a previous-local overload.

Nothing legacy was retired; the legacy renderers never supported skinning. Engine wiring stays with item 56.

## Defects found

- **Third-party:** fastgltf 0.9's node parser returns `InvalidGltf` for every node-level `weights` array (`if (weightsError != Error::None)` guards the success path). The pinned dependency is not patched. The limitation is documented, and the fixture sets node weights on the intermediate model instead.
- **Code:**
  - Two animator members named after their types (`AnimatorDesc::Skeleton`, `AnimatedSkeleton::Animator`) changed the meaning of the names under GCC's `-Wchanges-meaning`. They are now `SharedSkeleton` and `Controller`.
  - The first version packed unused influence slots as joint 0, which remapping turned into a real joint index. Unused slots now repeat the strongest joint.
- **Test-only:** a history test expected the constructor's rest pose to count as the previous palette. By design, the first update has no motion.
