# Item 39 desktop validation — September 12, 2026

The pasted failures had a common setup cause: SDK validation layer 1.3.296 was too old for the requested synchronization/GPU profiles. Core validation alone passed, so it did not reveal the remaining defects.

## Fixes

- **Loader lifetime:** vk-bootstrap retained process-global function pointers into SDL's loader after platform teardown unloaded it. Subsequent loads could relocate the DLL, causing access violations in `vulkan-1.dll_unloaded`. vk-bootstrap now owns its loader reference for the lifetime of its cached dispatch. SDL still owns platform/WSI references.
- **Sampled image formats:** Slang inferred SPIR-V `R32ui` for an unsigned sampled-image array containing both `R32_UINT` and `R8_UINT` views. SPIR-V compilation now defaults unspecified image formats to `Unknown`; explicit writable-image formats remain intact. A regression inspects the generated `OpTypeImage` operands. Reflection rejects explicit sampled-image storage formats that the numeric-class-only RHI interface cannot represent.
- **GPU validation configuration:** GPU-AV explicitly requests its shader-integer, storage-buffer, scalar-layout and memory-model prerequisites. Checks for mesh/ray APIs that Swim does not enable are disabled explicitly. Core validation runs separately before GPU-AV, following Khronos's recommendation; `all` combines synchronization and GPU-AV, with core off. Synchronization supports layer 1.4.335+, while GPU-AV requires 1.4.350+: the older 1.4.341 layer enabled an unsupported ray-hit checker without exposing its disabling setting. Version-specific ray-query naming is handled across 1.4.350/1.4.357.
- **SDK selection:** the Windows wrapper discovers current SDK layers, supports `-VulkanSdkPath`, respects an existing `VK_LAYER_PATH`, reports the selected path/version, and restores the environment. It does not download or install anything. Runtime setup failures include the detected version and settings availability.
- **Architecture verification:** machine-specific-path checks now prune build output, dependency caches, Git metadata, cooked output, and the historical archive before traversal. Maintained source remains checked.

## Acceptance policy

Every profile fails on errors, lost diagnostics, and unexpected warnings through instance teardown. The user approved exactly one startup advisory: GPU-AV setting `VkPhysicalDeviceDescriptorIndexingProperties::maxUpdateAfterBindDescriptorsInAllPools` to **4,194,304**. Its warning severity, complete text and count remain in the output. The exception requires an exact message ID/text match and the GPU profile. Different limits, feature forcing, disabled instrumentation, all other warnings, and any errors/drops still fail. Regression tests cover those rejection paths.

`core` and `sync` have core checks enabled. `gpu` and `all` have core checks disabled and must follow a separate passing core run. Shader instrumentation and supported GPU checks remain enabled. `GetValidationConfiguration()` reports submitted configuration, not introspection of every internal layer option.

## Reproduction

Use a supported desktop and current validation layer, with no conflicting Vulkan Configurator/environment overrides. Windows SDK selection and the four commands are documented in [README](../../README.md#vulkan-rhi-desktop-validation). For strict HDR, enable HDR for the desktop, set `SWIM_REQUIRE_HDR_SMOKE=1`, and select `RHI.Vulkan.Smoke.HdrNegotiationResizeMinimizeRestore`.

For Linux, build the same RHI/shader targets with the pinned Linux Slang SDK. When sharing the Windows dependency cache from WSL, set `SWIM_SLANG_CACHE_ROOT` to a separate Linux SDK cache so its extracted compiler does not replace the Windows compiler. Select the current SDK's `x86_64/share/vulkan/explicit_layer.d` with `VK_LAYER_PATH`. On a desktop supporting minimize/restore, run:

```bash
for profile in core sync gpu all; do
  SWIM_RUN_RHI_SMOKE=1 SWIM_RHI_VALIDATION="$profile" SDL_VIDEODRIVER=x11 \
    ./build/linux-debug/SwimTests --filter=RHI.Vulkan.Smoke --verbose \
    --report="build/rhi-linux-$profile.xml" || exit
done
```

For a virtual desktop, run those commands under `xvfb-run -a -s '-screen 0 1280x720x24 -nolisten tcp'`, start `openbox --sm-disable` inside that display, and wait for its `_NET_SUPPORTING_WM_CHECK` root property before launching the tests. Shut down the window manager after the run.

The nineteen cases verify actual Vulkan resource allocation, shader execution/readback, synchronization, presentation, and window lifecycle. They do not migrate the game to the modern RHI, validate RenderGraph, or establish performance across all GPUs. The legacy game-renderer transition and broader GPU coverage remain separate work.
