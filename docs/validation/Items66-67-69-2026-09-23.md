## Defects found

- **Integer attachments cannot be cleared through the RHI.** `LoadOp::Clear` rejects integer color formats, so the object-id target is `R32Float` (exact ids below 2²⁴), not `R32Uint`. This was found by reading the Vulkan rendering validation before any GPU run.
- **Depth attachment layout.** Rendering always uses the attachment layout, so the transparent pass declares depth `DepthStencilWrite` (read-write) even though its pipeline never writes depth. A `DepthStencilRead` declaration would have produced a layout mismatch.
- **Test-only:** a `SWIM_CHECK_EQUAL` on a scalar structured buffer's element size (reflection reports 0 for non-struct elements) was replaced by the binding-type checks, and a tangent check in the fixture test now uses constant-v edges only.

**Fixes:**

- **`WARNING-Shader-OutputNotConsumed` (the failure).** The transparent variant's vertex stage wrote `ObjectId` (location 5), but its fragment stage never reads it. `ObjectId` is now declared and written only in the opaque variant.
- **Per-pass timings overlapped.** `RenderGraphExecutor` writes each pass's begin timestamp at the top of the pipe before its barriers. A cheap pass that follows expensive work therefore reported the tail of that work: the 5-draw sort showed 6 ms, and the clustering `write` pass showed 0. `GraphPassTiming` gained `EndOffsetNanoseconds`, and the smokes now charge each pass the interval between consecutive end timestamps.

**How to read these numbers:** the per-pass values above came from the overlapping attribution. For example, `write` showed 0 even though it runs the same loop as `count`, so treat only the totals as indicative. The next desktop run prints end-to-end-attributed times. Record them here before setting budgets or closing the two scaling criteria in the plan.
