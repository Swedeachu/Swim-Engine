### Native smoke design

The smoke builds a 64×64 grid of two-LOD quads in a `GeometryHeap` and a `GpuScene`. It routes every 13th object to material bin 1, which has capacity 8 so that it overflows on purpose, and renders three frames into a 256×256 target through `DrawIndexedIndirectCount` for every bin:

1. A fresh LOD history.
2. A camera move, plus edits: three objects hidden, two destroyed, one moved out of view and two re-binned.
3. A camera cut with `ResetLodHistory`.

For each frame it reads back commands, draw records, counts, statistics and the image, and requires:

- exact statistics equality with `RunVisibilityReference`, including `Dropped > 0` and use of both LODs;
- the attempted per-bin counts;
- `FirstInstance == bin.First + slot`;
- every command belongs to the reference's candidate set, with exact set equality for unclamped bins;
- every drawn object's id at its sample pixel;
- no pixel belonging to an object that was not drawn.

The LOD margins of the chosen camera positions were checked numerically (smallest margin ≈ 0.0047 of the threshold), so float differences between CPU and GPU cannot flip a LOD.

## Defects avoided

- A zero-draw `DrawIndexedIndirect` originally reached the driver. It now validates and then records nothing.
- Default stride arguments were not visible through `VulkanCommandList&`. The Vulkan overrides now repeat them.
- The first Windows run (RTX 4070 Laptop GPU) failed only the smoke's pixel samples, which came out mirrored vertically; commands, counts and statistics already matched the CPU reference. The RHI uses +Y-up NDC and flips the Vulkan viewport, but the test mapped NDC to rows with Vulkan's native Y-down convention. The sample row is now `(0.5 - ndcY / 2) * height`.
- The smoke's pixel check first indexed transforms by object id. It now uses the drawn row's `TransformIndex`, because rows and ids are independent.
