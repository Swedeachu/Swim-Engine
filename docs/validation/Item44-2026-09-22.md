## Defect found and fixed

LeakSanitizer showed that **every** `AsyncIoService` read leaked its request state, including the file bytes: `IoRequestState::Work` held the job handle, and the job function captured the same request by `shared_ptr`. The leak predated this checkpoint (the existing IO suite reproduced it) but would have grown without bound under streaming. The job now captures a `weak_ptr` (tracking keeps the request alive until its completion is pumped), and `PumpCompletions` moves each callback out before invoking it so callbacks that capture their own request cannot form a second cycle.
