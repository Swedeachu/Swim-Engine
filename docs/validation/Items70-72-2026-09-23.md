## Defects found

- **The opaque depth program failed RHI interface conversion.** Its fragment stage took the vertex output struct, which held only `SV_Position`. Slang reflects such a parameter with no varying binding, so `BuildRhiShaderInterface` rejected it as an unsupported layout. At runtime, pipeline creation would have failed. The fragment stage now takes no parameters, and `ShaderCompiler.ShadowLayout` loads both variants through the conversion.
- **Allocator stability.** The first allocator placed requests strictly in priority order. That let a resized or new higher-priority light take the tiles a lower-priority light held last frame, and a downgraded light re-placed every frame. The allocator now:
  - keeps every unchanged request's tiles first, downgraded or not;
  - places new requests around them;
  - displaces lower-priority kept tiles only when a request cannot fit even at `MinTile`;
  - grows downgraded tiles back when room frees.
  
  In the randomized test, most tiles are now reused across frames.
- **Cube-face crossing.** The normal offset can move a receiver across a cube-face boundary. Point lookups now select the face again for the offset point. Before, points near 45° edges were projected outside their face and read as lit.
- **PCF footprint and bias.** A fixed normal offset caused acne with a 5×5 kernel on sloped receivers. The offset now scales with `max(PcfRadius, 1)`.
- **Test-only:** the sampling fixture treats points inside a casting cube as occluded (the analytic ray caster cannot see a cube from inside). A scalar structured buffer's reflected element size (0) is no longer checked.

**GPU-assisted validation failed** both `ShadowedForwardPlusMatchesTheCpuReference` and `ClusteredForwardPlusMatchesTheCpuReference`, on the performance warning `GPUAV-Compile-time-general-buffer`. Every image and atlas comparison still matched. GPU-AV instruments each load, store and atomic through a Uniform/StorageBuffer access chain and warns above 75 per module. The shadow lookup had pushed the Forward+ programs from 83/78 to 125/120 such accesses (conservative count). The lookup was inlined twice, once per light loop, and each view was loaded twice.

Fixed:

- one light loop, so the shadow lookup is inlined once;
- member loads of the shadow views;
- loops that copy the transform and vertex once each (Slang otherwise re-loads at every use).

The programs are now at 72 (opaque), 67 (transparent), 36 (sort), 12 and 20 (shadow depth). The new `ShaderCompiler.GpuAvBudget` test counts the accesses in the compiled SPIR-V and fails any renderer program above 75, so this is caught without a GPU.

Re-run after the fix: every profile (core, synchronization, GPU-assisted, combined) passes all 36 native cases (user report, 2026-09-23).
